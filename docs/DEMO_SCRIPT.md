## Narration Script

**0:00-0:03 - Cold Open**  
Permits become accountability.

**0:03-0:12 - Guardian Map**  
ROOT starts on the map. Every highlighted canopy is tied to a live removal permit, a location, a deadline, and a developer history.

**0:12-0:21 - Case Timeline**  
Open one tree, and the case becomes a five-year guardian timeline: Day 1 intervention, Day 90 check, Month 12 audit, survival checks, and closure.

**0:21-0:32 - Agent Pipeline**  
Behind the panel, agents assemble the case fast: nearby trees, permit context, developer survival history, policy conflicts, and precedent search become one filing-ready brief.

**0:32-0:45 - Draft And File**  
The public comment is editable before anything leaves the system. The user reviews the evidence, adds the filing destination, and authorizes ROOT to file with NYC Parks.

**0:45-0:49 - Mail Submit**  
One click sends the Day 1 intervention to NYC.

**0:49-0:53 - Guardian Activated Email**  
Immediately, ROOT confirms the guardian is active and the schedule has started.

**0:53-0:57 - Day 90 Email**  
Day 90, ROOT records survival and queues the next audit.

**0:57-1:06 - Developer Ledger**  
Every outcome rolls into the developer ledger. Future permits inherit the record: promised replacements, verified survival, violations, exposure, and unaccounted trees.

**1:06-1:21 - MongoDB Architecture**  
MongoDB is the memory layer. Geospatial indexes power tree and permit discovery. Atlas Vector Search retrieves similar precedent cases. Briefings, jobs, exports, notifications, and outcomes persist the guardian trail. Locally, ROOT uses the Motor repository layer; in production, Gemini can reach Atlas through MongoDB MCP.

**1:21-1:26 - Close**  
ROOT for them. Every threatened tree gets an agent.
